# Impeccable — Project Design Context

## Design Context

### Users
Developers and LLM-agent builders exploring the AT Protocol. They hit `atproto.md` from a terminal, a docs link, or a shared card while figuring out how to dereference an `at://` URI, browse a repo, or discover who uses a lexicon. Context is a code editor / terminal at a desk. The job: understand what this API does in seconds and copy a working command.

### Brand Personality
Precise · infrastructural · unadorned. It is plumbing for the open web — confident and exact, never decorative for its own sake. Voice is a well-made CLI or a man page that someone actually cared about.

### Aesthetic Direction
**Terminal / systems tool, dark.** Monospace-forward (legitimately — the product *is* a console for protocol data, not mono-as-shorthand). Console framing: status bar, prompt-style hero, endpoints as an aligned routing table, real terminal command blocks. Hairline rules and exposed structure over cards and shadows. One sharp signal accent used sparingly (~10%).

- Theme: dark, near-black tinted toward the accent hue.
- Accent: electric lime (signal/online), NOT bluesky-blue, NOT AI cyan/purple, NOT cliché green-on-black.
- Type: distinctive technical mono for display/structure/code (Martian Mono) paired with a refined grotesque for prose (Hanken Grotesk). Never the reflex fonts (Inter, Space/IBM Plex Mono, etc.).
- Anti-references: generic SaaS dashboards, glassmorphism, gradient text, left-accent stripes, rounded-card grids, hero-metric templates.

### Design Principles
1. **The page is a console.** Framing, prompts, and a routing table do the explaining — show the tool by being the tool.
2. **Structure over decoration.** Hairline rules, alignment, and rhythm carry the design; no shadows-on-cards, no gimmick effects.
3. **Signal is rare.** Lime accent marks only what's active or actionable. Everything else is neutral.
4. **Mono with intent, prose with care.** Technical mono for structure/commands; a real body face for sentences so reading never fatigues.
5. **One orchestrated motion moment.** A single staggered load + a steady cursor; transform/opacity only; honor reduced-motion.
